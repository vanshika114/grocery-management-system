# Security Policy

## Supported Versions

We take the security of our project seriously. Currently, only the latest major release is actively supported with security updates.

| Version | Supported          |
| ------- | ------------------ |
| v1.0.x  | :white_check_mark: |
| < v1.0  | :x:                |

## Reporting a Vulnerability

Please do **not** report security vulnerabilities through public GitHub issues, discussions, or pull requests. 

Instead, please report them using **GitHub Security Advisories**:
1. Go to the [Security tab](../../security/advisories) of this repository.
2. Click on **Report a vulnerability**.
3. Provide a descriptive summary and detailed steps to reproduce the vulnerability.

Alternatively, if the Security Advisory feature is unavailable, please email `vanshika114@github.com`.

### What to include in your report:
- Type of issue (e.g., buffer overflow, SQL injection, cross-site scripting).
- Full paths of source file(s) related to the manifestation of the issue.
- The location of the affected source code (tag/branch/commit or direct URL).
- Any special configuration required to reproduce the issue.
- Step-by-step instructions to reproduce the issue.
- Proof-of-concept or exploit code (if possible).
- Impact of the issue, including how an attacker might exploit the issue.

### Response Target (SLA)
- **Acknowledgment:** Within 48 hours of your report.
- **Triage & Assessment:** Within 5 business days.
- **Resolution:** Critical vulnerabilities will be addressed in a patch release within 14 days.

We will keep you updated throughout the process. Once the vulnerability is resolved, you may be acknowledged in our release notes (unless you prefer to remain anonymous).
